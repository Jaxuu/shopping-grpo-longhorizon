## 4. 奖励版本演进

| 版本 | 核心变更 | 判定语义 | 文档 |
|---|---|---|---|
| v3 | 基线：hard gate（category + budget，严格 `actual <= upper`）+ 维度加权 | — | `docs/reward-v3.md` |

**v5 的设计约束**（已写成断言，见 `tests/test_reward_v5.py`）：

- `driver = 0` 时与 v4 完全一致（最坏情形不变）；
- `cap(−0.66) < repeat_loop(−0.65) < max_steps(−0.50) < early_abstain(−0.35)`：档位序保持，
  `wrong_purchase` 仍是最差档（否则等于恢复恐慌性购买）；
- 轴用 `ms × prox` 而非纯 `ms`：23 题里 20 题是超预算失败，且 `ms` 与超支幅度
  Spearman **+0.42**（越像正确答案的商品越贵）。

### 5.1 真正的瓶颈：模型只开一个商品就下单（2026-10-19，更正前一版结论）

**先更正**：本节原先写的是「唯一失分维度是 `key_options`、417 条从没选规格」。那组数字取自
训练池探针，而且口径是**循环的**——它统计「有没有选金标变体那个规格轴」，可那些行里模型买的是
**另一个商品**，金标的规格轴根本不在页面上，必然"没选"。在 Final-200 上重算，结论完全不同。
以下数字全部可由 `outputs/evaluation/sft-b-curriculum/trajectories.jsonl`（200 行，M5-B，62.0%）复现。

**失败卡在哪一环**（76 条失败）：

| 环节 | 条数 | 占失败 |
|---|---:|---:|
| A 正确商品从没出现在任何搜索结果里 | 23 | 30% |
| B 出现在搜索结果里，但没打开 | 35 | 46% |
| C 打开过正确商品却没买 | 0 | 0% |
| D 买对了商品，但规格/维度没满分 | 18 | 24% |

**根因是一个动作，不是四个问题**：**198/200 条轨迹里 `open_product` 只被调用 1 次**，
且都是 `search_products → open_product` 紧挨着。每题用 8 步（149 条）或 9 步（37 条），
出现最多的序列是

```
search_products → open_product → select_option → view_features → prev_page → view_description → prev_page → buy_now
```

即：**搜一次、开第一个候选、买它**。所谓"核验"步骤发生在选择已经确定之后，不参与决策。

**这条策略从哪来**：SFT 池 1,252 条里 **1,117 条（89.2%）只开 1 个商品**，1,112 条只搜 1 次，
出现最多的序列（341 条）与上面那条 8 步模板逐字相同。⇒ **学生忠实地复制了老师"只看一个候选"
的策略**——不是学不会，是学得太好。

**这条策略的天花板**：把 200 题按「第一次搜索的第 1 名是不是正确商品」切开：

| | 题数 | 成功率 |
|---|---:|---:|
| 第 1 名就是正确商品 | 106 | **86.8%** |
| 第 1 名不是 | 94 | **34.0%** |

⇒ 成功率几乎完全由「一次搜索的第一个结果」决定。**62.0% 是"单候选策略"的天花板。**

**因此 M8 原方案（补规格核验示范）靶点错了**：规格维度只解释 18/76 = 24% 的失败；
真正的大头是 58/76 = 76% 的「没把正确商品纳入比较」。补规格示范对规格轴也已证明无效
（现有池 794 条 gold 轨迹在下单前就写出了要选的规格值），对新靶点才有讨论价值。

**两条可复用的教训**：
1. `bought_gold_failed_gate` 桶只按 `purchased_asin == gold_asin` 分组，不检查硬门；
   「买对商品但规格没选全」和「超预算」会落在一起。分桶必须再拆一层。
2. **任何"模型没做 X"的统计，必须先确认它当时有没有机会做 X。** 本次两版错误结论都源于
   没做这一步。

### 5.2 M9 两轮诊断皆负：强制"多看几个"没用，真正的靶点是"抄错规格"（2026-10-19 夜）

§5.1 把靶点定在「没把正确商品纳入比较」，于是设计了 M9：**只加一条环境规则
（买前必须打开过 k 个不同候选），权重/题目/解码全不动**，看成功率动多少。

**第一轮 k=5 —— 作废，测的是步数耗尽。** 模型确实配合了（6 题里 5 题开到 3–6 个），
但 `max_steps` 在环境侧**硬冻结 35**（`configs/environment.json` 的
`termination.max_steps`；`SHOP_MAX_STEPS` 与冻结值不同会直接抛 `ValueError`，**不可调**），
而这个模型对每个候选都走完整仪式
`open → select_option → view_features → prev → view_description → prev → back_to_search → search`
= **8 步/候选**。5 个候选需 42 步 ⇒ 2×`max_steps`、1×`repeat_loop`、1×error、**0/6 成功**。
这个仪式**不是守卫逼出来的**：基线 task 7684（无守卫）逐字复现同一序列。

**第二轮 k=3 —— 步数问题解决，分数却崩了。** 18–27 步、**0 条 `max_steps`**、
每题稳定开 3 个，但同批 9 题：

| task | 基线 | M9 k=3 |
|---|---|---|
| 8187 / 17354 / 5833 / 11282 / 11213 / 15576 / 18324 | **gold 1.0**（7 题） | 5×`partial_alternative` + 2×`wrong_purchase` |
| 9610 | `repeat_loop` | `error` |
| 14877 | `partial_alternative` | `partial_alternative` |

**基线 7/9 → 0/9；7 失 0 得**，7 个不一致对全同向，McNemar p≈0.016。而且这 9 题是题库最前
9 题（基线 77.8%，比整体更容易），不存在"后面翻盘"的可能。

**机制是结构性的，不是模型偶然**：环境只允许买**当前打开的那个商品**（`buy_now` 无参数），
所以"多看几个"在物理上等于"买最后一个"。而搜索排序本身已按相关度排，
第 1 名就是正确商品时成功率 86.8%（§5.1）⇒ **买最后一个严格劣于买第一个**。
逐题核对：7 题里正确商品都排在**第 1 个**打开，模型最终买的是**第 3 个**。
根子是模型没有"回到之前候选再下单"这个动作——SFT 池 135 条多候选轨迹里只有 57 条会回头，
占全池 **4.6%**。

（另一个叠加伤害是我自己造成的：为省步数，我在守卫提示里写了
「不要 select_option / view_features / view_description」，**顺手砍掉了基线的核验动作**。
两个变量混在一起，已在本轮结论中一并记录，不再单独归因。）

⇒ **「多候选比较」这条杠杆在推理期不可测、在当前模型上不可用。** 不是"探索没用"，
是模型没有把探索结果用起来的能力。M8 的"补多开示范"方向随之作废。

**转而解剖 D 桶（18 条「买对商品却没满分」）**，口径收紧到 `purchase.asin == goal.asin`
（此时正确商品的规格轴必然在页面上，不再循环），工具
`scripts/analyze_option_selection_failures.py`：

| 观测 | 数值 |
|---|---|
| 只卡在 `key_options` 一个维度 | **18/18** |
| 要求值在页面上「原文逐字可见」 | 11 |
| 要求值「仅大小写/标点/转义不同」 | 8 |
| 要求值**真的不在页面上** | **0** |

典型形态全是「挑了一个相近的变体」：要求 `145升高配版/PCM钢胆/减霜80%/零下27度`，
选了 `301升高配版 | pcm钢胆 | 减霜80% | 零下30度`；要求 `a559`，选了 `a554`；
要求 `米家电子温湿度计Pro`，选了 `米家空调伴侣2`。

⇒ 这是**照抄失败**，不是判断失败，也不是"没机会"。**下一轮靶点 = 规格字符串精确匹配**，
上界 +18 题 = **+9pp → 71.0%**。这条路不需要新动作、不需要跨候选比较、不与环境冻结契约冲突，
且可离线验证——与已被否掉的两条（补数据量、提 lr）相比，它是目前唯一"证据指向、代价可控"的。

### 5.3 三条路全部关闭：62.0% 是这套配方的天花板（2026-10-19 夜，纯 CPU）

§5.2 把靶点定在 D 桶（规格抄错）之后，必须先回答一个前置问题：**SFT 池里有没有教过这种
"在一堆近似变体里挑对"的场景？** 如果没有，补数据有用；如果已经有，补同类就是白费
（§5.1 已经踩过一次）。答案是有，而且是足量的：

| 观测（`data/sft_pure_v4/all.jsonl`，1,252 行**全部是 gold 轨迹**） | 数值 |
|---|---|
| 可定位到轴与候选列表的 `select_option` 次数 | 1,633 |
| 所选轴只有 1 个候选（根本没得选） | 330 |
| 所选轴候选数 ≥10 | 424 |
| 与最近兄弟值相似度 ≥0.9 / 0.8–0.9 | 340 / 293（合计 **38.7%**） |
| **含「近似变体且候选 ≥3」这种难例的行** | **543 / 1,252 = 43.4%** |

而 D 桶那 18 题在难度上**并不出格**：要求值长度中位 14（池子 p90 是 20），
候选数中位 6（池子均值 8.2）。⇒ **难度在分布内，示范量也够，模型仍然错。**
⇒ **D 关闭：不是数据覆盖问题，是 2B 的残余误差，再补同类示范无效。**

接着用同一把尺子量 A 桶（正确商品从没出现在搜索结果里的 20 条）。
把商品语料（本地 23,421 条，`fine_items_eval_train_all.json.gz`）拉进来，
算「正确商品标题的 2-gram 有多少落在用户指令里」：

| 分组 | n | 标题覆盖率中位 |
|---|---:|---:|
| 成功 | 124 | **0.26** |
| B 见过没打开 | 53 | 0.21 |
| **A 从没出现** | **20** | **0.09** |

A 桶的正确商品标题与用户措辞**几乎不共享任何词**（覆盖率只有成功组的 1/3）。
用户说"炼乳 小份 10g"，商品标题写的是"甜酱 面包 馒头 小包装"；
用户说"洗地机 一体化 自动清洁"，商品写"吸拖洗一体机 自清洁"。
**索引是词面的，词表对不上，换任何"忠实于指令"的查询都捞不到。**
⇒ **A 关闭：不是查询写得好不好的问题，是词表鸿沟。**

三条路的状态汇总：

| 桶 | 题数 | 上界 | 判定 | 证据 |
|---|---:|---:|---|---|
| A 正确商品从没出现在结果里 | 20 | +10pp | **关闭** | 标题覆盖率 0.09 vs 成功组 0.26，词表鸿沟 |
| B 出现过却没打开 | 35 | +17.5pp | **关闭** | 环境只能买当前商品；强制多看 = 买最后一个，实测 7/9→0/9；SFT 池仅 4.6% 有"回头"动作 |
| C 打开过却没买 | 0 | — | — | — |
| D 买对商品但规格抄错 | 18 | +9pp | **关闭** | 池里 543 条同类难例且全为 gold；难度在分布内，再补无效 |

⇒ **62.0% 是「2B + 当前 SFT 数据 + 冻结环境」这套配方的天花板**，与作者自己那轮 GRPO 的
62.0% 一致（+1.5pp，p≈0.664）。想真正抬高天花板只剩两条：**换更大底座**，
或**改任务定义**（等于改考卷，不解决能力）。

**一个尚未验证的旁证（不是方案）**：`sft-a`（118）与 `sft-b`（124）在 200 题上
只有 106 题共同成功、30 题只有一个成功，**并集 136 = 68.0%**，两路买同一商品 78%。
说明"多样性"本身有约 +6pp 的空间，但那是 oracle 上界，不是可实现的收益；
多采样投票要 5 倍推理成本，且多数失败看起来是系统性的，预期收益不明。
